# SCP:SL 服务端提示（Hint）内部实现解剖

> 基线：本机 public 分支 **14.2.x** 的 `Assembly-CSharp-Publicized.dll`（2026-11-23 反编译）。
> 15.0「Megapatch III」尚未正式发布，本文把 15.0 的变化点单列为「待核对」，发布当天按 §11 的清单逐条复核。
> 目的：把 HintChorus 从「会打补丁」推进到「真正理解提示管道」——知道哪些能控、哪些不能控、代价是什么。

---

## 0. 结论先行

1. **服务端只负责构造对象和序列化，不做任何布局。** 字号、行距、换行、字体回退、颜色解析全部在客户端 TMP 完成。
2. 提示的**唯一语义入口**是 `Hints.HintDisplay.Show(Hint)`；它只发给该 `HintDisplay` 所属玩家，**没有广播 API**。
3. 提示的**唯一网络出口**是 `HintMessage`；`SuppressedReceivers` 是官方留出的「按连接静音」开关。
4. `Hint` 是一个多态对象：`TextHint`（纯文本）与 `TranslationHint`（客户端译文枚举）两种。
5. 时长字段 `DurationScalar` 是**倍率**，不是绝对秒数；客户端还有一个未公开的基础时长。
6. `HintParameter` 有 20 种，其中弹药/物品/分类/按键是**客户端本地化**的；倒计时是**逐帧更新**的。
7. 把第三方提示合并成一条 `TextHint` 会丢失动态参数与效果；要做「HSM 级中间层」，必须区分「可静态合并」与「必须保留对象」的提示。
8. 15.0 的 DisplayKit 是另一条 UI 管道（UI Toolkit），不是 Hint 的新序列化；两条管道要并存协调，而不是互相替代。

## 2. 类型地图

| 类型 | 角色 | 关键成员 |
| --- | --- | --- |
| `ReferenceHub.hints` | 每玩家一个提示接收器 | `public HintDisplay hints` |
| `Hints.HintDisplay` | 服务端入口组件（`NetworkBehaviour`） | `Show(Hint)`, `static HashSet<NetworkConnection> SuppressedReceivers` |
| `Hints.HintMessage` | 网络消息 | `readonly Hint Content` |
| `Hints.Hint` | 抽象基类 | `HintParameter[] Parameters`, `HintEffect[] _effects`, `float DurationScalar` |
| `Hints.TextHint` | 纯文本提示 | `string Text` |
| `Hints.TranslationHint` | 客户端译文提示 | `HintTranslations Translation`（6 个枚举） |
| `Hints.HintParameter` | 抽象参数 | `string Formatted`, `UpdateState(float progress)` |
| `Hints.HintEffect` | 抽象效果 | `StartScalar`, `DurationScalar` |
| `Hints.HintEffectPresets` | 效果预设 | `FadeIn` / `FadeOut` / `FadeInAndOut` / `PulseAlpha` / `TrailingPulseAlpha` |

`HintDisplay.Show` 的完整反编译（关键部分）：

```csharp
public void Show(Hint hint)
{
    if (hint == null) throw new ArgumentNullException("hint");
    if (isLocalPlayer) throw new InvalidOperationException("Cannot display a hint to the local player (headless server).");
    if (NetworkServer.active)
    {
        NetworkConnection networkConnection = netIdentity.connectionToClient;
        if (!SuppressedReceivers.Contains(networkConnection))
            networkConnection.Send(new HintMessage(hint));
    }
}
```

要点：

- `hint == null` 直接抛异常；中间层必须保证不把 null 传回去。
- `isLocalPlayer` 在无头服务器上恒为 false；若在客户端主机模式调用会抛异常。
- **只有 `NetworkServer.active` 才发**；纯客户端调用是空操作。
- `SuppressedReceivers` 是静态集合，按 `NetworkConnection` 静音；这是官方开关，不依赖 Harmony。
- 发送目标是 `netIdentity.connectionToClient`，即该 `HintDisplay` 的拥有者——**每条提示天然是「对某个玩家」的**。

## 3. 调用链

```
插件 / LabAPI
   └─ Player.SendHint(...) / ReferenceHub.hints.Show(new TextHint(...))
        └─ HintDisplay.Show(Hint)
             ├─ null / isLocalPlayer / NetworkServer.active 检查
             ├─ SuppressedReceivers.Contains(connectionToClient)
             └─ connectionToClient.Send(new HintMessage(hint))
                  └─ Mirror 序列化
                       └─ 客户端 HintDisplay 接收 → TMP 渲染（IL2CPP，服务端不可见）
```

LabAPI 的包装（`LabApi.Features.Wrappers.Player`）：

```csharp
public void SendHint(string text, float duration = 3f)
    => SendHint(text, new[] { new StringHintParameter(string.Empty) }, null, duration);

public void SendHint(string text, HintEffect[] effects, float duration = 3f)
    => ReferenceHub.hints.Show(new TextHint(text, new[] { new StringHintParameter(string.Empty) }, effects, duration));

public void SendHint(string text, HintParameter[] parameters, HintEffect[]? effects = null, float duration = 3f)
    => ReferenceHub.hints.Show(new TextHint(text,
        !parameters.IsEmpty() ? parameters : new[] { new StringHintParameter(string.Empty) },
        effects, duration));
```

注意：LabAPI 默认塞一个**空的** `StringHintParameter`；文本本体在 `TextHint.Text`，参数只负责占位/格式化。这与「`TextHint` 的文本里可以出现参数占位」并不冲突——参数会被客户端按顺序格式化，但 `TextHint.Text` 本身是最终字符串。

## 4. 线格式（逐字节）

### 4.1 Hint 多态头

`Utils.Networking.HintReaderWriter`：

| 值 | 类型 |
| --- | --- |
| 0 | `TranslationHint` |
| 1 | `TextHint` |

写：`byte type` + `hint.Serialize(writer)`。

### 4.2 Hint 基类负载

`Hints.Hint.Serialize`：

```
float  DurationScalar
int    effectCount          // -1 表示 null
repeat effectCount:
    byte effectType         // 0 Alpha / 1 AlphaCurve / 2 Outline
    float effect.DurationScalar
    float effect.StartScalar
    ... effect payload
int    parameterCount       // -1 表示 null
repeat parameterCount:
    byte parameterType      // 0..19
    ... parameter payload
```

### 4.3 两种 Hint 的附加字段

| 类型 | 附加负载 |
| --- | --- |
| `TextHint` | `string Text` |
| `TranslationHint` | `byte Translation`（`HintTranslations` 枚举） |

`HintTranslations` 6 项：

```
WarheadDetonateCoverDenied
MaxAmmoReached
MaxAmmoAlreadyReached
MaxItemCategoryReached
MaxItemCategoryAlreadyReached
MaxItemsAlreadyReached
```

这 6 项对应客户端 `GameHints` 翻译文件的 6 行；HintChorus 的 `NativeHintTranslator` 与 `docs/translations/*.txt` 就是围绕这张表做的。

### 4.4 参数类型表

`Utils.Networking.HintParameterReaderWriter.HintParameterType`（byte）：

| 值 | 类型 | 负载 |
| --- | --- | --- |
| 0 | `StringHintParameter` | `string Value` |
| 1 | `TimespanHintParameter` | `double SourceTime`, `string Format`, `bool Negate` |
| 2 | `AmmoHintParameter` | `int Id` |
| 3 | `ItemHintParameter` | `int Id` |
| 4 | `ItemCategoryHintParameter` | `int Id` |
| 5 | `ByteHintParameter` | `byte` |
| 6 | `SByteHintParameter` | `sbyte` |
| 7 | `ShortHintParameter` | `short` |
| 8 | `UShortHintParameter` | `ushort` |
| 9 | `IntHintParameter` | `int` |
| 10 | `UIntHintParameter` | `uint` |
| 11 | `LongHintParameter` | `long` |
| 12 | `ULongHintParameter` | `ulong` |
| 13 | `FloatHintParameter` | `float` |
| 14 | `DoubleHintParameter` | `double` |
| 15 | `PackedLongHintParameter` | 压缩 long |
| 16 | `PackedULongHintParameter` | 压缩 ulong |
| 17 | `Scp330HintParameter` | SCP-330 专用 |
| 18 | `SSKeybindHintParameter` | `int Value`, `string Format` |
| 19 | `AnimationCurveHintParameter` | 曲线 |

可格式化的原始类型（`FormattablePrimitiveHintParameter<T>`）会额外写一个 `string Format`。

### 4.5 效果类型表

`HintEffectType`（byte）：0 `Alpha`、1 `AlphaCurve`、2 `Outline`。

| 类型 | 附加负载 |
| --- | --- |
| `AlphaEffect` | `float Alpha` |
| `AlphaCurveHintEffect` | 继承 `CurveHintEffect`：`AnimationCurve` |
| `OutlineEffect` | `Color32 OutlineColor`, `float OutlineWidth` |

所有效果都先写 `DurationScalar` 与 `StartScalar`。

### 4.6 数组编码

`ArrayReaderWriter<T>.WriteArray`：

- `null` → 写 `int -1`，不写元素；
- 非 null → 写 `int Count`，再逐个写。

读取时 `count < 0` 返回 null。

## 5. 时长语义

- `TextHint` / `TranslationHint` 构造函数默认 `durationScalar = 3f`；`DisplayableObject` 默认 `1f`。
- `HintEffect` 的 `DurationScalar` / `StartScalar` 都是相对提示生命周期的比例（`HintEffectPresets` 的 `FadeInAndOut(window, durationScalar, startScalar)` 直接按比例算）。
- **客户端还有一个基础显示时长**，不在服务端程序集里；`DurationScalar` 是它的倍率。这就是为什么 HintChorus 把 `duration` 当「秒」用在实际观感上基本对，但严格说不是协议保证。
- 15.0 若调整客户端基础时长或改字段含义，服务端的「秒」假设会失效；`docs/15.0-displaykit-plan.md` 的 T9 验证项要覆盖这一点。

## 6. 参数、本地化与动态性

这一节决定「中间层能不能合并」。

| 参数 | 是否客户端本地化 | 是否动态 |
| --- | --- | --- |
| `StringHintParameter` | 否（原文） | 否 |
| `AmmoHintParameter` | 是：`TranslationReader.Get("Ammo", id)` / 物品名 | 否 |
| `ItemHintParameter` | 是：物品 nametag | 否 |
| `ItemCategoryHintParameter` | 是：`TranslationReader.Get("Categories", id)` | 否 |
| `SSKeybindHintParameter` | 是：`KeyCodes` + 客户端按键绑定 | 否 |
| `TimespanHintParameter` | 否（格式字符串） | **是**：`UpdateState(progress)` 逐帧返回当前倒计时 |
| 原始数字类型 | 按 `Format` | 否 |
| `AnimationCurveHintParameter` | 否 | 曲线采样 |

关键结论：

1. **静态合并只对 `TextHint` + 非动态参数安全。** 把倒计时参数压成字符串会冻结在合并那一刻。
2. `Ammo` / `Item` 的文字由客户端语言决定；服务端合并时拿不到最终文本，只能保留参数对象或放弃合并。
3. HintChorus 当前对原生提示的做法是「用内嵌译文模板翻成纯文本再合并」，这本质上牺牲了动态性，换来稳定排版；对一次性提示（弹药上限、物品上限）是可接受的。
4. 若要做 HSM 级「保留对象」的中间层，需要按玩家维护「参数对象列表」，并在每次刷新时重新构造 `TextHint`，而不是拼接字符串。这是 15.x 的架构升级方向，不在 15.0.0 范围内。

## 7. 抑制、接管与补丁竞争

现有 HintChorus 的三层：

| 层 | 落点 | 作用 |
| --- | --- | --- |
| 语义层 | `HintDisplay.Show` Prefix（`int.MaxValue`） | 读 `Hint` 对象、归因、决定吸收/放行 |
| 兜底层 | `HintDisplay.Show` Postfix | 前缀被更高优先级插件跳过时，强制重发复合块 |
| 网络层 | `NetworkConnection.Send<T>`（可选哨兵） | 观察绕过语义层的直发 |

官方还留了一个**不打架**的开关：

```csharp
HintDisplay.SuppressedReceivers.Add(connection);    // 该连接不再收到原生 Show
HintDisplay.SuppressedReceivers.Remove(connection); // 恢复
```

它只影响 `HintDisplay.Show` 的发送，不改对象、不改其它通道；适合「某玩家暂时由我们的 UI 接管」这种场景。代价是：其它插件调用 `Show` 会「以为发送成功」，实际被静默丢弃——所以只能在明确要接管时用，并且要提供 `take`/`reset` 恢复路径。

补丁竞争要点（已在 1.1.2 验证）：

- 外部 `Harmony.Unpatch(HintDisplay.Show, HarmonyPatchType.All)` 会把整表清空；仲裁层在同一调用栈内恢复。
- 外部前缀返回 `false` 会跳过我们之后的所有前缀，但 **Postfix 仍执行**；`HintDisplayShowPatch` 用 `[ThreadStatic] _prefixRan` 区分「我们看过」与「我们被跳过」。
- `Show` 的签名只有 `(HintDisplay __instance, Hint hint)`；15.0 若加参数/改返回类型，所有补丁点要重写。

## 8. 客户端渲染边界（IL2CPP）

服务端能确定的：

- TMP 富文本标签（`<color>` / `<b>` / `<i>` / `<size>` / `<align>` / `<pos>` / `<voffset>` / `<line-height>` 等）由客户端解析；HintChorus 的排版就是基于这些标签。
- 客户端语言决定 `TranslationHint` 与 `Ammo`/`Item` 等参数文本。
- 15.0 客户端使用 Unity 6000.4，并针对 Roboto / Roboto Mono 做了文字位置修正（见 `docs/15.0-displaykit-plan.md`）。

服务端**不能**确定的：

- 实际字体、字号、行距、换行宽度、CJK 回退字体；
- TMP 版本对未知标签的容错行为；
- 客户端是否对超长文本做裁剪/滚动。

因此：

- `TextMetrics` 只能做**宽度估算**（内嵌 `HintChorus.textwidth.bin` 是字形 advance 表，不含 kerning 与自动换行）；
- 「位置绝对稳定」只能靠固定行数 + `<voffset>` 锁定，不能靠测量真实渲染高度；
- 15.0 的 CJK 回退必须实机截图验证，不能只靠服务端推断。

## 9. 与 15.0 DisplayKit 的关系

| 维度 | Hint（本文） | DisplayKit（15.0） |
| --- | --- | --- |
| 渲染基础 | 客户端 TMP | Unity UI Toolkit |
| 服务端模型 | `Hint` 对象 + 参数/效果 | `DisplayCanvas` → `DisplayElement` / `DisplayText` |
| 布局 | 无（文本标签自救） | flexbox（服务端声明） |
| 同步 | `HintMessage` 单条消息 | 画布/元素属性脏标记同步 |
| 语言 | `TextHint` 原文 / `TranslationHint` 枚举 | 文本由服务端给，字体不含 CJK |
| 中间层策略 | 拦截、合并、回退 | 默认只观测，不接管 |

结论：DisplayKit 不是 Hint 的替代品，而是第二后端。HintChorus 15.0.0 保持 Legacy Hint 为默认后端；DisplayKit 探测层只做类型/方法探测与报告，等 15.0 正式程序集落地后再接 T4/T9。

## 12. 未解问题

1. 客户端基础提示时长与 `DurationScalar` 的精确换算（需要实机计时）。
2. 15.0 TMP 是否仍支持 `<voffset>` / `<pos>` / `<line-height>` 全套标签。
3. DisplayKit 字体是否提供 CJK 回退；没有时中文服需要自备字体方案。
4. `SuppressedReceivers` 在 15.0 是否保留；若删除，只剩补丁路径。
5. `TimespanHintParameter` 的 `SourceTime` 基准（`NetworkTime.time`）在 15.0 是否改变——这会影响倒计时合并策略。
