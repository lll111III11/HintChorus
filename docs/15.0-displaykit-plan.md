### 2. DisplayKit 是什么

- **服务端权威、网络同步的 UI 框架**，构建在 **Unity UI Toolkit（Unity 6000.4）** 之上。
- 核心模型：`DisplayCanvas` → `DisplayElement` / `DisplayText`，flexbox 布局，样式分组（Background/Flex/Align/Size/Spacing/Border/Position/Transform/Display/Text）。
- 支持**全局画布**与**每玩家画布**、`Spawn` / `Show` / `Hide` / `SetVisibility`、自动脏标记同步。
- 官方文档：LabAPI Wiki 的 8 个 `DisplayKit*.md` 页面（已下载到本地 `displaykit-preview/wiki/`）。
- 关键 API 示例：

```csharp
DisplayCanvas canvas = DisplayCanvas.Create();
canvas.DefaultVisibility = CanvasVisibility.Visible;
DisplayText text = canvas.AddText("Welcome");
text.Text.FontSize = 48f;
canvas.Align.AlignItems = Align.Center;
canvas.Spawn();                 // 全局
canvas.Spawn(connectionId);     // 指定玩家
```

### 3. 15.0 的引擎与文字度量变化

- 15.0 客户端使用 **Unity 6000.4**；14.2.x 仍是旧 Unity（例如 `WhiteSpace` 没有 `Pre/PreWrap`）。
- 15.0 客户端对 Roboto / Roboto Mono 的文字位置有专门修正：
  - 含 CJK 的行按微软雅黑 ascender 1.058 / descender 0.262 计算；
  - CJK 字形下沉 1px；
  - Roboto / Roboto Mono 自动高度标签 **+2px**。
- DisplayKit 自带字体（Inter / Roboto / Roboto Mono / Liberation Sans）**不包含 CJK 字形**；15.0 客户端是否有字体回退、回退到哪一款，官方文档没有写死。

## 二、DisplayKit 对 HintChorus 的影响矩阵

| 现有能力 | 15.0 后的风险 | 处理方向 |
| --- | --- | --- |
| `HintDisplay.Show` 拦截（TMP 提示条） | 老插件继续用 Hint，签名可能随 Unity 6000.4 变化 | 发布后逐条核对补丁落点；保留 `Hint orvs` 回退 |
| Broadcast / Console / CASSIE / AdminChat / HitMarker | 可能被 15.0 新 UI 或 DisplayKit 取代/并存 | 继续拦截旧通道；新增 DisplayKit 通道识别，避免重复渲染 |
| 多插件合并与位置锁定 | DisplayKit 自身有全局/每玩家画布与层级，可能与合并层“抢屏” | 增加「DisplayKit 画布优先级/可见性」协调；默认不接管 DisplayKit 网络消息 |
| 文本度量（TextMetrics） | 15.0 有专门的客户端文字修正 | 把 15.0 修正纳入 TextMetrics；增加 CJK 回退检测 |
| `UiIsolation.SendHint`（零配置写法） | 15.0 插件可能直接改用 DisplayKit | 增加 `DisplayKit` 后端：同一调用在 15.0 自动走 DisplayKit，旧版走 Hint |
| `Hint orvs` 回退 | 只覆盖被拦截的 Hint 插件 | 增加 `orvs` 对 DisplayKit 画布的“停止接管/放行”语义 |
| 详细 UI 日志 | 需要覆盖 DisplayKit 画布/属性写入 | 日志增加 Canvas/Spawn/Visibility/PropertyWrites 事件 |

## 三、更新计划（P0 / P1 / P2）

### P0 — 15.0 发布前必须准备好

- [ ] **DisplayKit 探测层**：启动时反射检测 `DisplayKit` 程序集/类型；不编译期硬引用，避免 14.2.x 加载失败。
- [ ] **双后端设计**：
  - `HintBackend.Legacy`：现有 TMP Hint 合并（14.2.x 默认）。
  - `HintBackend.DisplayKit`：15.0 检测到 DisplayKit 时可用；把 `UiIsolation.SendHint` 映射为 `DisplayCanvas` + `DisplayText`。
  - 配置项建议：`displaykit_mode: auto | off | prefer`。
- [ ] **不接管 DisplayKit 网络消息**：DisplayKit 自己就是隔离框架，HintChorus 只观测/记录，默认不拦截，避免双重同步。
- [ ] **15.0 补丁落点核对表**：`HintDisplay.Show`、Broadcast 增删、`GameConsole.SendToClient`、CASSIE、AdminChat、HitMarker、`IntercomDisplay.Serialize`、`AspectRatioSync`。
- [ ] **补丁自愈兜底**：15.0 发布当天若某个补丁装不上，自动降级为“只保留能装的通道”，并在报告日志中标记缺失目标。
- [ ] **`Hint orvs` 扩展**：支持把 DisplayKit 后端切回旧 Hint / 完全放行；命令帮助同步更新。

### P1 — 发布前后完成

- [ ] **15.0 文字度量**：把 `docs/reference.md` 的三条修正并入 `TextMetrics`（CJK ascender、CJK 1px 下沉、Roboto +2px），并保留 `client/reference` 两套模式。
- [ ] **CJK 回退检测**：启动时检测 15.0 客户端是否给 DisplayKit 提供 CJK 回退；没有则报警并在日志中列出缺字文本。
- [ ] **位置/层级协调**：DisplayKit `SortOrder` 与 HintChorus 合并块之间的层级规则；避免提示条被画布完全盖住。
- [ ] **详细 UI 日志扩展**：记录 DisplayKit canvas id、global/per-player、visibility、property/structure writes。
- [ ] **预览场景**：把 HintChorus 的典型 UI（状态条、任务进度、效果列表）写成 DisplayKit scenario，提前比对 15.0 观感。

### P2 — 正式版发布后 24 小时内

- [ ] 用 15.0 Dedicated Server 的 `Assembly-CSharp.dll` 重新跑 `tools/verify-patches.ps1`。
- [ ] 核对 DisplayKit 真实命名空间/类型/方法（对照 `docs/reference.md#guesses` 的 20 条猜测）。
- [ ] 跑一遍真实 15.0 客户端截图，与 HTML/Unity 渲染器比对（`python dkpreview.py compare`）。
- [ ] 更新 `patch-target-report.txt`、README、CHANGELOG、插件站简介。
- [ ] 如果 LabAPI 发布 15.0 适配版，重新编译并回归测试。

## 六、风险与未知项

1. **DisplayKit 未正式发布**：Wiki 与真实程序集可能有差异；`docs/reference.md#guesses` 已列出 20 条猜测，发布后必须逐条核对。
2. **CJK 支持未知**：DisplayKit 字体不含 CJK，客户端回退方案未公开；中文服可能出现方框/错位。
3. **Unity 6000.4 升级**：不仅影响 UI，也可能影响 Harmony 补丁目标、TMP、输入系统；需要整体回归。
4. **LabAPI 15.0 适配时间未知**：如果 LabAPI 滞后，HintChorus 需要先保证“能加载、能降级”，再谈新功能。
5. **DisplayKit 与旧 Hint 并存**：两套 UI 同时存在时可能出现层级/可见性冲突，需要实测后定规则。

---

## 七、结论

15.0 不是“换一套贴图”的更新，而是**UI 基础设施换代**：DisplayKit + Unity UI Toolkit + 新文字度量。HintChorus 的下一步不应只继续加 Hint 拦截规则，而应：

1. 保留现有 Legacy Hint 后端（兼容旧插件）；
2. 新增 DisplayKit 后端（15.0 自动探测、反射调用、默认只观测不接管）；
3. 把 15.0 文字度量与 CJK 回退纳入布局层；
4. 用 `displaykit-preview` 提前把典型 UI 场景跑起来；
5. 正式版发布后 24 小时内完成补丁落点与真实客户端比对。
