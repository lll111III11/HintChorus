================================================================================
HintChorus 自有位置写法规范 v1
================================================================================
面向读者: 想让自己的提示落在指定屏幕位置的插件作者
配套文件: docs/api-guide.zh.txt ｜ README.md「位置：三类写法合一」

一句话: 写一个短标记, 或调用一个方法, 就能把提示钉在屏幕上你想要的位置。

--------------------------------------------------------------------------------
0. 为什么需要"写法"
--------------------------------------------------------------------------------
游戏只给一个提示口, 所有插件的文字会被拼成一条下发。谁先谁后、落在哪一行,
原本完全不可控 —— 这就是"装很多插件后 UI 互相顶掉 / 上下乱跳"的根因。
HintChorus 把这件事变成可以"声明"的: 你只需说明"我要放在哪", 其余交给底层统一排版。

--------------------------------------------------------------------------------
1. 三个维度
--------------------------------------------------------------------------------
每个位置由三个维度描述(后两个可省略):

  纵向(Vertical)   ← 必填, 二选一
      ① 九宫格锚点:  top-left | top | top-right
                     middle-left | middle | middle-right
                     bottom-left | bottom | bottom-right
      ② 0-1000 标尺: 0 = 屏幕底, 500 = 屏幕中, 1000 = 屏幕顶

  横向(Horizontal)  ← 可选; 省略时由锚点所在列推导(左列→左, 右列→右, 中列→居中)
      align = left | center | right

  微调(Offset)      ← 可选
      offset = <数字>    (voffset 单位, 正 = 上移; 参考: 整屏约 2140)

--------------------------------------------------------------------------------
2. 两个通道, 同一套语法
--------------------------------------------------------------------------------
通道 A · 文本标记(零依赖, 不引用本插件也能用)
    在提示文本的任意位置写 {{hc:...}}, 底层解析后会把标记整段剥掉 —— 玩家看不到。

        player.ShowHint("{{hc:top-right}} 得分 12");
        player.ShowHint("{{hc:pos=750,align=left,offset=-90}} 目标指示");

通道 B · C# API(引用本插件的作者)
    using HintChorus.Core.Layout;

    UiIsolation.SetHintPosition("MyPlugin", HintAnchor.MiddleCenter, -90f);
    UiIsolation.SetHintPosition("MyPlugin", "pos=750,align=left");   // 同一套语法
    UiIsolation.ClearHintPosition("MyPlugin");                       // 撤销, 回到自动推断

两个通道解析的是同一段字符串 —— 所以插件的配置项里也可以直接存这个字符串,
文本标记、配置项、C# 代码三处通用。

--------------------------------------------------------------------------------
3. 完整语法
--------------------------------------------------------------------------------
    {{hc:<体>}}        体 = 若干"项", 用逗号或分号分隔, 顺序任意, 大小写不敏感

  项                       含义                       取值
  -----------------------  -------------------------  -----------------------------------
  <锚点名>                 (裸写)九宫格锚点           top-right / middle / 右上 / mc ...
  <数字>                   (裸写)0-1000 标尺          750
  pos=<锚点名 或 数字>     锚点 或 标尺               pos=top-right | pos=750
  anchor=<锚点名>          锚点                       anchor=中部
  y=<数字>                 标尺                       y=500
  scale=<数字>             标尺                       scale=1000
  offset=<数字>            微调(正=上移)              offset=-90
  voffset=<数字>           同上                       voffset=40
  align=<左/中/右>         横向对齐                   align=left | align=右

  锚点别名(节选):
      tl / tr / tc      ml / mr / mc      bl / br / bc
      top / bottom / middle
      左上 / 右上 / 中上    中左 / 中右 / 中部    左下 / 右下 / 中下
  对齐别名:
      left | l | start | 左 | 居左 | 靠左
      center | c | middle | 中 | 居中
      right | r | end | 右 | 居右 | 靠右

--------------------------------------------------------------------------------
4. 示例
--------------------------------------------------------------------------------
    {{hc:top-right}}                          右上角(横向自动靠右)
    {{hc:750}}                                0-1000 标尺的第 750 高度
    {{hc:pos=750,align=left}}                 同一高度, 但横向靠左
    {{hc:middle,offset=-90}}                  屏幕中部, 再往下 90
    {{hc:pos=500,offset=-90,align=center}}    标尺 + 微调 + 显式对齐
    {{hc:bc}}                                 底部居中(等同默认)

    UiIsolation.SetHintPosition("LevelHUD", "pos=500,offset=-90");

--------------------------------------------------------------------------------
5. 解析优先级(谁说了算)
--------------------------------------------------------------------------------
    ① 显式 API  (SetHintPosition)
    ② 自有文本标记  ({{hc:...}})
    ③ 插件自带位置标签  (<voffset> / <pos> / <align> / <line-height> /
                          <line-indent> / <indent> / <margin>) → 原样放行
    ④ 已收录表 / 功能区名称推断
    ⑤ 默认: 底部中央自然堆叠

  说明: ③ 一旦命中, 本底层对这条提示"彻底放手" —— 连横向对齐都不覆盖。
        这是为了让从 RueI / HintServiceMeow / 原生 TMP 过来的 UI 位置一动不动。

--------------------------------------------------------------------------------
6. 配置项
--------------------------------------------------------------------------------
  honor_plugin_position_syntax  (默认 true)   是否兼容 ③
  auto_layout_by_plugin_name    (默认 true)   是否启用 ④
  enable_position_markers       (默认 true)   是否识别并剥离 {{hc:...}}
  screen_height_units           (默认 2140)   "整屏"折算成多少 voffset 单位
  position_overrides            (默认空)      服主覆盖表, 语法同上:

        position_overrides:
          LevelSystem: middle,offset=-90
          MyPlugin: pos=750,align=left

--------------------------------------------------------------------------------
7. 与生态的对应关系
--------------------------------------------------------------------------------
  RueI / ruei-cm-lab 的 Scaled position(0-1000)  →  本项目 pos=<0-1000>, 数值可照抄
      其源码: baseline = 755 - 2.14 * pos;  2.14 * 1000 = 2140, 正是 screen_height_units 默认值
  HintServiceMeow 的 XCoordinate/YCoordinate      →  其产物带位置标签, 走 ③ 原样放行
  原生 TMP <voffset> / <pos> / <align> / ...      →  走 ③ 原样放行

--------------------------------------------------------------------------------
8. 常见问题
--------------------------------------------------------------------------------
  Q: 标记会被玩家看到吗?
  A: 不会。解析后整段剥掉; 只有关掉 enable_position_markers 才会原样显示(排障用)。

  Q: 会和别的框架的 {0} 模板冲突吗?
  A: 不会。本标记是双大括号 {{ }}, 且在我们的解析里先于其它模板处理。

  Q: 顶部 / 中部位置偏了怎么办?
  A: 调 screen_height_units(整屏折算), 一个键搞定; 也可用 offset 逐条微调。

  Q: 多个插件放在同一位置会怎样?
  A: 同一位置区按优先级稳定排序后纵向堆叠, 不会互相顶掉。

  Q: 我只想让某个插件换个位置, 不想改它代码?
  A: 用 position_overrides 覆盖即可, 语法与上面完全一致。
